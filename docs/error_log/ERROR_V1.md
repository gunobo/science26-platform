# ERROR_V1: 1307 학생 "배포가 안 돼요"

| 항목 | 내용 |
| --- | --- |
| 보고 | 2026-11-19, 1307 학생 (정적 웹, 링크 이름 `biiouwz`) |
| 증상 | 새 버전을 올려서 배포할 수가 없음. 다른 학생은 정상 |
| 원인 | 과목을 고르지 않은 프로젝트는 업로드 버튼이 막히는데, 화면에는 항상 "지금 빌드가 진행 중이에요"라고 잘못 안내함 |
| 분류 | 프론트엔드 (대시보드 안내 문구·화면 흐름) |
| 해결 | 막힌 이유를 정확히 보여 주고, 업로드 카드 안에서 바로 과목을 고를 수 있게 함 |
| 함께 고친 것 | worker 로그에 디스코드 웹훅 주소(토큰 포함)가 찍히던 문제 |

---

## 1. 증상

- 1307 학생만 "배포가 안 된다"고 함. 같은 시간에 다른 학생들은 정상적으로 올리고 배포함.
- 학생은 대시보드에 로그인해 화면을 계속 새로 고치고, 로그아웃했다가 다시 로그인하기도 함.

## 2. 조사 과정

서버(NCP)에 SSH로 접속해 DB와 컨테이너 로그를 차례로 확인했다.

### 2-1. 활동 기록 (`audit_logs`)

```sql
select a.at, a.action, u.role
from audit_logs a left join users u on u.id = a.actor_id
where a.target = '1307' order by a.at;
```

| 시각 (UTC) | 동작 | 비고 |
| --- | --- | --- |
| 10-28 | register | 정적 웹으로 처음 등록 |
| 11-03, 11-04 | upload | 마지막 정상 업로드 (v4) |
| 11-10 | update_info | 이용 가이드북 올림 |
| 11-18 02:59 | rollback **v4 → v4** | 같은 버전 다시 배포 |
| 11-18 03:01 | stop | |
| 11-18 06:31 | start | |
| 11-18 06:37 | rollback **v4 → v4** | 같은 버전 다시 배포 |
| 11-19 07:53 | admin_stop, delete | 관리자가 프로젝트 삭제 |

- 11-04 이후 **upload 기록이 한 번도 없다.** 대신 '같은 버전 다시 배포'와 중지·시작을 반복했다.
- **과목(`과목: …`)을 고른 기록이 없다.**

### 2-2. 서버 쪽 실패가 있었는지

- worker 로그: 1307의 `deploy_existing`, `stop_project`, `start_project`, `delete_project` 모두 성공(●). 재배포 뒤 헬스 체크도 `200 OK`.
- API 로그: 학생 접속 기간 동안 `POST /api/v1/projects/me/releases`(업로드) 요청이 **하나도 없다.** 실패한 요청(4xx·5xx)도 없다.
- 삭제 뒤 학생이 다시 로그인한 것을 `users.last_login_at`으로 확인했다. 그 뒤에도 `GET /projects/me` 같은 조회만 반복되고 업로드 요청은 없었다.

→ 서버가 업로드를 거절한 게 아니라, **브라우저에서 업로드 요청 자체가 나가지 않았다.** 프론트엔드 문제로 범위를 좁혔다.

### 2-3. 프론트엔드 코드

`web/src/screens/DashboardScreen.tsx`

```tsx
{!project.subject && !project.deleting && <SubjectCard onChange={refresh} />}
<UploadCard disabled={busy || !project.subject || !!project.deleting} ... />
...
<Button label="올리고 배포하기" ... disabled={disabled} />
{disabled && <T variant="small">지금 빌드가 진행 중이에요. 끝나면 다시 올릴 수 있어요.</T>}
```

- 업로드 버튼은 **빌드 중**, **과목 미선택**, **삭제 중**일 때 막힌다.
- 그런데 버튼 옆 안내는 이유와 상관없이 늘 **"지금 빌드가 진행 중이에요"**였다.

### 2-4. 왜 "얘만" 안 됐나

- 과목 선택은 2026-11-01(커밋 `13764ee`)에 생겼다. 그 전에 프로젝트를 만든 학생은 `subject`가 빈 값이다.
- 1307은 과목을 한 번도 고르지 않았다 → 업로드 버튼이 계속 막힘.
- 화면에는 "빌드 중"이라고 나오니 학생은 빌드가 끝나기를 기다리거나, 대신 '같은 버전 다시 배포'·중지·시작을 눌렀다. 2-1의 기록과 정확히 맞는다.
- 다른 학생들은 과목을 이미 골랐거나, 과목이 생긴 뒤에는 새로 올린 적이 없어서 드러나지 않았다.

```sql
select count(*) total, count(*) filter (where subject = '') no_subject from projects;
-- total 59, no_subject 10  (조사 시점)
```

과목이 빈 프로젝트가 **10개 더** 있다. 이 학생들도 새 버전을 올리려고 하면 똑같이 막힌다.

## 3. 원인

**과목을 고르지 않으면 업로드가 막히는데, 화면이 그 이유를 "빌드 중"이라고 잘못 알려 줬다.** 과목 카드가 화면 위쪽에 따로 있어서, 업로드 카드만 보는 학생은 무엇을 해야 하는지 알 수 없었다.

## 4. 해결

`web/src/screens/DashboardScreen.tsx`

1. **막힌 이유를 따로 구분**: `disabled: boolean` 대신 `blocked: 'deleting' | 'subject' | 'building' | null`을 넘긴다.

   | 이유 | 버튼 옆 안내 |
   | --- | --- |
   | 삭제 중 | 프로젝트를 지우는 중이에요. 끝나면 올릴 수 있어요. |
   | 과목 미선택 | **과목을 먼저 골라야 올릴 수 있어요.** |
   | 빌드 중 | 지금 빌드가 진행 중이에요. 끝나면 다시 올릴 수 있어요. |

2. **업로드 카드 안에서 바로 과목 선택**: 과목이 없으면 업로드 버튼 바로 위에 노란 안내와 과목 버튼(물리학·화학·생명과학·지구과학)이 나온다. 고르면 바로 업로드 버튼이 풀린다.
3. 과목 고르기 코드를 `SubjectChooser`로 분리해, 위쪽 과목 카드와 업로드 카드가 같이 쓴다.

확인한 것:

- 가짜 API로 '과목 없는 학생' 대시보드를 띄워, 안내와 과목 버튼이 업로드 버튼 위에 나오는 것을 확인했다.
- 타입 검사(`npm run typecheck`)와 백엔드 테스트(`pytest`, 120개)가 통과했다.

## 5. 함께 고친 것: 로그에 웹훅 토큰 노출

조사 중 worker 로그에 다음과 같은 줄이 계속 찍히는 것을 발견했다.

```
INFO:httpx:HTTP Request: POST https://discord.com/api/webhooks/<id>/<token> "HTTP/1.1 204 No Content"
```

httpx가 요청 URL을 통째로 INFO로 남기기 때문에, 디스코드 웹훅 주소(토큰 포함)가 로그에 그대로 남는다. 서버 로그를 볼 수 있는 사람은 누구나 알림 채널에 글을 쓸 수 있게 된다.

- `api/app/worker.py`의 `startup()`에서 `logging.getLogger("httpx").setLevel(logging.WARNING)`
- **이미 남은 로그에는 토큰이 들어 있으므로 디스코드에서 웹훅을 새로 만들고, 서버 설정의 웹훅 주소를 바꾸는 것이 안전하다.**

## 7. 배운 점

- 버튼을 막을 때는 **왜 막혔는지**를 그대로 보여 줘야 한다. 이유가 여럿인데 안내가 하나뿐이면 사용자는 엉뚱한 행동을 반복한다.
- 필수 항목을 나중에 추가하면, **이미 있는 데이터(기존 프로젝트)**가 그 조건을 못 채운 채 남는다. 추가할 때 기존 데이터를 어떻게 할지 같이 정해야 한다.
- "서버 로그에 실패가 없다"는 것도 단서다. 요청이 아예 오지 않았다면 클라이언트 쪽을 봐야 한다.
