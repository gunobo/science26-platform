# science26 학생 사용 설명서

내가 만든 과학 프로젝트를 올리면 **science26.bssm.dev** 에 내 페이지가 바로 생겨요.
웹사이트, 백엔드가 있는 웹앱, 모바일 앱까지 올릴 수 있어요.

| 주소 | 하는 일 |
|---|---|
| `https://science26.bssm.dev` | 전시관 (모든 친구들의 프로젝트) |
| `https://science26.bssm.dev/upload` | 내 프로젝트 올리기 (대시보드로 이동) |

---

## 1. 로그인

1. `https://science26.bssm.dev/upload` 접속 (전시관 오른쪽 위 **프로젝트 올리기** 버튼도 같아요)
2. **Google 계정으로 계속하기** → **학교 구글 계정**으로 로그인

> 💡 "학번 등록을 기다리고 있어요" 가 보이면 아직 선생님이 학번을 연결하지 않은 거예요. 선생님께 말씀드리고 잠시 뒤 새로고침하세요.
>
> 개인 Gmail 로는 로그인할 수 없어요.

---

## 2. 어떤 타입으로 올릴까?

| 내 프로젝트 | 타입 | 올리는 것 |
|---|---|---|
| HTML/CSS/JS, React·Vue(Vite), Expo Web 처럼 **서버 없이** 돌아가는 웹 | **정적 웹** | 빌드 결과 폴더 zip, 또는 `index.html` 하나 |
| 백엔드(Node, Python 등)나 **DB가 필요한** 웹 | **풀스택** | 프로젝트 전체 zip, 또는 GitHub 공개 저장소 주소 |
| 휴대폰 앱 | **모바일 앱** | APK·TestFlight 링크·시연 영상 중 하나 이상 + 스크린샷 |

> 💡 서버가 꼭 필요한 게 아니면 **정적 웹**이 가장 빠르고 안정적이에요.

---

## 3. 정적 웹 올리기

1. 대시보드 → **새 버전 올리기** → **정적 웹**
2. 빌드 결과 zip(최대 100MB) 또는 `index.html` 선택
3. **올리고 배포하기** → 몇십 초 뒤 **빌드 진행**에서 `✅ 배포 완료` 확인

### ⚠️ 경로 주의 (가장 많이 틀리는 부분)

내 페이지는 `science26.bssm.dev/students/내링크이름/` 아래에서 열려요. 그래서 `/` 로 시작하는 경로는 깨져요.

| ❌ 깨짐 | ✅ 동작 |
|---|---|
| `<script src="/app.js">` | `<script src="./app.js">` |
| `<img src="/logo.png">` | `<img src="logo.png">` |

- **Vite**: `vite.config` 에 `base: './'`
- **Create React App**: `package.json` 에 `"homepage": "."`
- **Expo Web**: `app.json` 의 `experiments.baseUrl` 을 `/students/내링크이름` 으로
- 페이지 이동(라우터)은 **해시 라우터**(`HashRouter`)가 가장 쉬워요

업로드할 때 `/` 로 시작하는 경로가 보이면 노란 경고가 떠요.

## 4. 풀스택 올리기

1. 대시보드 → **새 버전 올리기** → **풀스택**
2. **zip 업로드**(최대 200MB) 또는 **GitHub 저장소**(공개 저장소 주소 + 브랜치)
3. 빌드는 몇 분 걸릴 수 있어요. 빌드 로그를 보면서 기다리세요.

### 꼭 지켜야 할 규칙

- 프로젝트 맨 위 폴더에 **`docker-compose.yml`** 이 있어야 해요
- 서비스는 **최대 3개**
- 브라우저가 여는 서비스에 라벨 `science26.public: "true"`
- API 서버를 따로 뒀다면 그 서비스에 `science26.api: "true"` → `/students/내링크이름/api/` 로 열려요
- **쓸 수 없는 것**: `ports`, `volumes`, `privileged`, `restart`, `network_mode` 등
- **DB·Redis 서비스를 넣지 마세요.** 자동으로 하나씩 만들어 줘요
- 이미지는 Docker Hub **공식 이미지만** (`node:20-alpine` ⭕, `someone/app` ❌). 직접 만들 땐 `build` 사용

### 자동으로 들어가는 환경변수

| 이름 | 용도 |
|---|---|
| `DATABASE_URL` | 내 전용 PostgreSQL (1GB 넘으면 접속이 막혀요) |
| `REDIS_URL` | 내 전용 Redis 계정 (캐시 용도) |
| `REDIS_KEY_PREFIX` | Redis 키 앞에 **반드시** 붙일 값 |
| `BASE_PATH` | 내 페이지 경로 (`/students/내링크이름`) |
| `PUBLIC_URL` | 내 페이지 전체 주소 |

### 실행 환경

- 파일 저장 불가 (읽기 전용). 쓸 수 있는 곳은 `/tmp` 같은 임시 폴더뿐이고 재시작하면 사라져요 → 데이터는 **DB에 저장**
- 메모리 서비스당 256MB, CPU 0.5개
- `0.0.0.0` 에 열어야 해요 (`localhost` ❌)
- 개발 서버(`npm run dev`) 말고 실제 실행 명령으로 (`node server.js` 등)
- 첫 화면(`/`)이 **60초 안에** 열려야 배포 성공
- **30분 동안 아무도 안 들어오면 잠들어요.** 누가 열면 몇 초 뒤 다시 깨어나요

## 5. 모바일 앱 올리기

**아래 셋 중 하나 이상** + 스크린샷 1~5장 + 앱 이름·설명

| 항목 | 준비 |
|---|---|
| Android **APK** (선택) | 서명된 APK, 150MB 이하 |
| iPhone **TestFlight 링크** (선택) | `https://testflight.apple.com/join/...` |
| **시연 영상** (선택) | mp4·webm·mov, 100MB 이하 |

설치 버튼과 QR 코드가 있는 소개 페이지가 자동으로 만들어져요.

> 💡 iPhone 은 설치 파일을 직접 받을 수 없어요. 애플 개발자 계정이 없으면 **시연 영상**을 올리거나, Expo·Flutter 앱이면 **웹으로 빌드해서 정적 웹**으로 올려 보세요.

## 6. AI로 배포 준비하기 (Codex·Claude Code)

대시보드의 **AI로 배포 준비하기** 카드를 펼치면:

1. 프로젝트 폴더에서 **규칙 파일 받기** 명령 복사 → 터미널에서 실행
2. **AI에게 할 말** 복사 → Codex 나 Claude Code 에 붙여넣기
3. AI가 알려준 zip 이나 저장소를 대시보드에서 올리기

AI가 경로 설정, `docker-compose.yml` 작성까지 규칙에 맞게 고쳐줘요.

> ⚠️ API 키 같은 비밀값은 AI에게 주지 말고, 배포 후 **환경변수** 칸에 직접 넣으세요.

## 7. 배포한 뒤에

### 실행 관리 (대시보드)
- **중지 / 다시 시작**
- **로그 보기**: 내 앱이 출력한 로그 (풀스택은 서비스 이름으로 골라 볼 수 있어요)

### 배포 기록
- 버전마다 성공·실패와 빌드 로그가 남아요
- **이 버전으로**: 예전 버전으로 되돌리기 (롤백)

### 환경변수 (풀스택)
- **추가** → 이름과 값 → **비밀값으로 숨기기** 를 켜면 저장 후 다시 볼 수 없어요
- 저장하면 다음 배포부터 적용돼요

## 8. 마이페이지

| 기능 | 설명 |
|---|---|
| 내 정보 | 이름·이메일·학번 (틀렸으면 선생님께) |
| 전시관에 보이는 모습 | 내 카드 미리보기 |
| 전시관에 공개 | 끄면 목록에서만 사라지고, 링크로는 계속 열려요 |
| 링크 이름 | 영문 소문자·숫자·하이픈 1~32자. 바꾸면 자동으로 다시 배포돼요 (학번 주소로 들어와도 새 주소로 연결) |
| 제목·설명·썸네일 | 전시관 카드에 보여요 |
| 프로젝트 삭제 | 페이지·기록·파일·DB가 **모두 지워지고 되돌릴 수 없어요**. 링크 이름을 입력해야 삭제돼요 |

> ⚠️ **업로드 마감** 이후에는 올리기와 삭제가 막혀요.

## 9. 자주 겪는 문제

| 증상 | 해결 |
|---|---|
| 페이지가 하얗게 나와요 / CSS가 안 먹어요 | `/` 로 시작하는 경로를 상대경로로 (3번) |
| "이미 빌드·배포가 진행 중입니다" | 이전 빌드가 끝날 때까지 기다리기 |
| "요청이 너무 많습니다" | 업로드는 10분에 5번까지. 잠시 후 다시 |
| `COMPOSE_FORBIDDEN_KEY` | `ports`, `volumes` 같은 금지 키 지우기 (4번) |
| 헬스체크 실패 | `0.0.0.0` 에 열었는지, `/` 가 60초 안에 응답하는지 확인 |
| "깨우는 중" 화면 | 30분 동안 방문이 없어서 잠든 것. 몇 초 뒤 자동으로 열려요 |
| 새로고침했더니 404 | 해시 라우터를 쓰거나 서버에서 없는 경로를 `index.html` 로 |
